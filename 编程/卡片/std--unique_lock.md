## unique_lock

- 一个通用的互斥量锁定包装器，它允许延迟锁定，限时深度锁定，递归锁定，锁定所有权的转移以及与条件变量一起使用。
- 简单地讲，uniquelock 是 lockguard 的升级加强版，它具有 lock_guard 的所有功能，同时又具有其他很多方法，使用起来更强灵活方便，能够应对更复杂的锁定需要。
- 特点如下：
    - 创建时可以不锁定（通过指定第二个参数为std::defer_lock），而在需要时再锁定
    - 可以随时加锁解锁
    - 作用域规则同 lock_grard，析构时自动释放锁
    - 不可复制，可移动
    - 条件变量需要该类型的锁作为参数（此时必须使用unique_lock）

### unique_lock与lock_guard的区别

- lock_guard:
    - 锁定方式：构造时锁定，析构时解锁。
    - 灵活性：不提供对互斥体的手动控制。当lock_guard对象创建时，它会自动尝试锁定给定的互斥体，当lock_guard对象析构时，它会自动解锁互斥体。
    - 用途：当你只需要保护一段固定的作用域并且不需要更多的灵活性时，它是理想的选择。

```C
std::mutex mtx;
void function() {
    std::lock_guard<std::mutex> lock(mtx); // mtx被锁定
    // ... 在此处进行受互斥体保护的操作 ...
    // 在函数返回或退出作用域时，mtx自动解锁
}
```

- unique_lock
    - 锁定方式：可以在构造时锁定，也可以稍后锁定。同样，可以在析构时解锁，也可以更早解锁。
    - 灵活性：提供了更多控制。你可以手动锁定、解锁，甚至转移锁定的所有权。此外，它支持延迟锁定、尝试锁定等。
    - 其他功能：与 std::condition_variable 一起使用，或进行某种形式的尝试锁定。
    - 用途：当你需要更多的灵活性、手动控制或与其他同步工具一起使用时，它是理想的选择。

```C
std::mutex mtx;
void function() {
    std::unique_lock<std::mutex> lock(mtx, std::defer_lock); // 创建，但不立即锁定
    // ... 可能进行一些操作 ...
    lock.lock();  // 现在锁定mtx
    // ... 在此处进行受互斥体保护的操作 ...
    lock.unlock(); // 可以手动解锁
    // ... 可能进行更多操作 ...
    lock.lock();  // 可以再次锁定
    // 在函数返回或退出作用域时，如果互斥体被锁定，它将自动解锁
}
```

---

- lock_guard 提供了一个简单、不可重新锁定、无法手动解锁的锁机制。
- unique_lock 提供了更多的灵活性，允许延迟锁定、手动锁定/解锁和转移锁定的所有权，但相应地带来了一些额外的开销
