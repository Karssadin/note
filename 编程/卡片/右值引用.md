## 右值引用

函数参数可以不可以传递右值(值传递、右值引用、函数模板的转发引用)?

---

- [从4行代码看右值引用](https://www.cnblogs.com/qicosmos/p/4283455.html)
- 右值引用的主要目的是为了实现**转移语义和完美转发**，消除两个对象交互时不必要的对象拷贝，也能够更加简洁明确地定义泛型函数
- 左值：左值是一个可以定位到存储空间的表达式。变量、返回左值引用的函数调用、前置自增/自减、赋值/复合复制运算、*解引用
- 右值：右值是临时的，不能绑定到左值引用上（除非是常量左值引用）
    - 纯右值：字面值、非引用类型返回的函数调用、运算表达式（算数、逻辑、后置自/）产生的临时变量、原始字面量和lambda表达式
    - 将亡值：这些值通常不再需要其资源，可以直接移动或窃取资源，而不进行复制。用来触发移动构造和移动赋值构造，进行资源转移，之后会调用析构函数。将要被移动的对象、返回右值引用的函数、std::move返回值（将左值转换为右值引用）等

### 左值引用

- 左值引用就是对左值进行引用的类型，是对象的一个别名，必须立即初始化
- 对于左值引用，等号右边的值必须可以取地址，如果不能取地址，则会编译失败，或者可以使用常量左值引用形式
- **常量左值引用可以指向任何类型的对象上，包括临时对象，但是不能修改这个值。右值引用是对这个的改进**

### 右值引用

- 左值引用是对左值进行绑定，但不能绑定右值
- 对右值进行绑定的引用就是右值引用，语法是Type &&，通过双引号来表示绑定类型为A的右值
- 通过右值引用可以延长临时右值的生命周期
- 通过std::move()可以指绑定左值到右值引用
- 左值引用和右值引用的变量是左值
- move显式地将其参数转换为右值引用（R-value reference），从而允许对象的资源在某些情况下被"移动"而不是被"复制"

### 左值、右值的区别

- 非常量左值无法引用右值
- 常量左值引用是一个“万能”的引用类型，可以接受左值，右值，常量左值、常量右值。
- 左值可以当右值使用，但右值不可以当左值使用
- 简单说，左值以变量的形式存在，指向内存，生命周期比较长，我们可以对左值进行各种操作；而右值通常以常量的形式存在，是一个临时值，不能被程序的其它部分访问，生命周期很短
- 左值，可以看作是存储在内存中的，有明确存储地址（可寻址）的数据；右值，指的是可以提供数据值的数据（不一定可以寻址，比如常量是存储于寄存器中的数据）
- 当一个对象被用作右值时用的是对象的值；当被用作左值时，用的是对象的存储空间

- 左值引用和右值引用的区别?
    - 对左值的引用，对右值的引用
    - 左值引用为了避免对对象的拷贝：函数传参，函数返回值
    - 右值引用：实现移动语义，实现完美转发

### 移动语义

- 移动语义：消除两个对象交互时不必要的对象拷贝，服务器链接资源、堆上内存、文件描述符
- 触发移动构造和移动拷贝构造
- unique_ptr使用到了移动语义、stl中的push_back等都用到了移动语义，对象需要有移动构造函数，方便调用
- 表达式等号右边的值需要是右值，可以使用std::move函数强制把左值转换为右值，move是将对象资源的所有权从一个对象转移到另一个对象，只是转移，没有内存的拷贝，这就是所谓的move语义。
    - 比如临时对象调用拷贝构造函数有很大的堆资源操作，使用move直接转移,
    - 唯一的功能是将一个左值强制转换为一个右值引用。如果是一些基本类型比如int和char[10]定长数组等类型，使用move的话仍然会发生拷贝（因为没有对应的移动构造函数），move对于含资源（堆内存）的对象来说更有意义

### 完美转发

- 如果不使用forward()则无法保证传递的参数类型与原始调用时的类型相同。可能会导致编译错误或者运行时错误。
    - 引用折叠：当使用完美转发时，通过 std::forward 可以避免引用折叠造成的问题。引用折叠是指当两个引用相遇时产生的一种现象，即一个左值引用和一个右值引用结合后得到一个 lvalue 引用，右值引用和右值传进来是右值、左值引用和左值传进来是左值引用。接受完值之后左值引用和右值引用都是左值，需要使用forward进行完美转发。
    - 如果没有使用 std::forward 进行完美转发，则可能会导致引用折叠带来的意外结果。由于引用折叠的影响，即使传递的是一个右值，也会得到一个左值引用，是一个左值。T为左值引用，将V转换为T类型的左值，T为右值引用，将T转换为T类型的右值

---

- 写一个接受任意实参的函数模板，并转发到其它函数，目标函数会收到与转发函数完全相同的实参，通过std::forward()实现
    
    - 在函数模板中，完全依照模板的参数的类型（即保持参数的左值、右值特征），将参数传递给函数模板中调用的另外一个函数。C++11中的std::forward正是做这个事情的，转发参数的值，同时也会转发值的实际左右值属性。看下面的- 右值引用T&&是一个万能引用，可以通过引用的方式接受左值或者右值，正是这个特性让他适合作为一个参数的路由，然后再通过std::forward按照参数的实际类型去匹配对应的重载函数，最终实现完美转发
    
    ```C
    void processValue(int& a){ cout << "lvalue" << endl; }
    void processValue(int&& a){ cout << "rvalue" << endl; }
    template <typename T>
    void forwardValue(T&& val){
        /*
        T& & 折叠为 T&
        T& && 折叠为 T&
        T&& & 折叠为 T&
        T&& && 折叠为 T&&
        */
        processValue(std::forward<T>(val)); //照参数本来的类型进行转发。
    }
    void Testdelcl(){
        int i = 0;
        forwardValue(i); //传入左值
        forwardValue(0);//传入右值
    }
    //输出：lvaue  rvalue
    ```

- 如果去掉forward()会怎么样？
    - 如果不使用std::forward并直接传递arg，则arg始终作为左值传递，即使原始参数是右值。这会影响性能并可能导致一些预期之外的行为。
    - 如果函数期望接收一个右值，并据此进行优化（如移动资源而不是复制资源），那么在不使用std::forward的情况下，这些优化就不会发生
