- 网络地址转换 (NAT) 是一种在本地网络和互联网之间实现地址转换的技术。其基本原理是将内部网络中的私有 IP 地址转换为公有 IP 地址，以便与外部网络通信。
- 大部分网络应用使用传输层协议 TCP 或 UDP。这为我们提供了一个额外的转换点：端口号。因此，我们不仅可以转换 IP 地址，还可以转换端口号，这种技术被称为网络地址和端口转换 **(NAPT)**。

---

- 考虑一个简单的场景，其中两个客户端（192.168.1.10 和 192.168.1.11）希望与外部服务器（183.232.231.172）通信。这两个客户端可能从相同的端口（例如1025）开始通信。在这种情况下：
- 两个客户端使用的私有 IP 地址都会被转换为相同的公共 IP 地址（例如，120.229.175.121），但端口号将不同以区分它们。
- NAPT 路由器将维护一个转换表，以确保返回的数据包能够正确路由到原始的内部客户端。这种转换表在 NAT 路由器上自动生成。例如，在 TCP 的情况下，建立 TCP 连接首次握手时的 SYN 包一经发出，就会生成这个表。而后又随着收到关闭连接时发出 FIN 包的确认应答从表中被删除。

---

- 由于 NAT/NAPT 都依赖于自己的转换表，因此会有以下的问题：
    - 外部无法主动与 NAT 内部服务器建立连接，因为 NAPT 转换表没有转换记录。
    - 转换表的生成与转换操作都会产生性能开销。
    - 通信过程中，如果 NAT 路由器重启了，所有的 TCP 连接都将被重置。
- 解决方法
    - 改用 IPv6:IPv6 可用范围非常大，以至于每台设备都可以配置一个公有 IP 地址，就不搞那么多花里胡哨的地址转换了，但是 IPv6 普及速度还需要一些时间。
    - NAT 穿越技术拥有这样的功能，它能够让网络应用程序主动发现自己位于 NAT 设备之后，并且会主动获得 NAT 设备的公有 IP，并为自己建立端口映射条目，注意这些都是 NAT设备后的应用程序自动完成的。在 NAT 穿透技术中，NAT设备后的应用程序处于主动地位，它已经明确地知道 NAT 设备要修改它外发的数据包，于是它主动配合 NAT 设备的操作，主动地建立好映射，这样就不像以前由 NAT 设备来建立映射了。就是客户端主动从 NAT 设备获取公有 IP 地址，然后自己建立端口映射条目，然后用这个条目对外通信，就不需要 NAT 设备来进行转换了
