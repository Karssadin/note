## 事务

事务是一个不可分割的数据库操作序列，也是数据库并发控制的基本单位，其执行的结果必须使数据库从一种一致性状态变到另一种一致性状态。事务是逻辑上的一组操作，要么都执行，要么都不执行。

经典例子：转账时将小明的余额减少 1000 元、将小红的余额增加 1000 元，这两个操作必须同时成功或同时失败。

### 事务定义与特性（ACID）

事务由 MySQL 的存储引擎实现，InnoDB 支持事务，MyISAM 不支持。

| 特性 | 含义 | InnoDB 实现 |
|------|------|------------|
| **原子性（Atomicity）** | 操作要么全部完成，要么全部不执行 | undo log（回滚日志） |
| **一致性（Consistency）** | 事务前后数据库完整性保持不变 | 由其他三者共同保证 |
| **隔离性（Isolation）** | 并发事务互不干扰 | MVCC + 锁机制 |
| **持久性（Durability）** | 提交后数据永久保存，即使崩溃也不丢失 | redo log（WAL 机制） |

### 脏读、不可重复读、幻读

- **脏读**：一个事务读取了另一个**未提交**事务的修改数据。若对方回滚，读到的就是"脏"数据。
- **不可重复读**：同一事务内多次读取**同一行**，结果不同（其他事务修改并提交了该行）。
- **幻读**：同一事务内执行相同的**范围查询**，返回的行数不同（其他事务插入了新行）。

严重性排序：脏读 > 不可重复读 > 幻读

### 事务隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|---------|------|-----------|------|
| 读未提交（READ UNCOMMITTED） | 可能 | 可能 | 可能 |
| 读提交（READ COMMITTED） | 不会 | 可能 | 可能 |
| 可重复读（REPEATABLE READ，默认） | 不会 | 不会 | InnoDB 通过间隙锁解决 |
| 串行化（SERIALIZABLE） | 不会 | 不会 | 不会 |

隔离水平排序：串行化 > 可重复读 > 读已提交 > 读未提交。级别越高越安全，但并发性能越差。

## Read View 与 MVCC

### MVCC 核心机制

每条聚簇索引记录包含两个隐藏列：
- `trx_id`：最后修改该记录的事务 ID
- `roll_pointer`：指向 undo log 中该记录的旧版本，形成**版本链**

当事务读取数据时，沿版本链向后遍历，直到找到一个对自己"可见"的版本。

### Read View 的关键属性

| 属性 | 含义 |
|------|------|
| `m_ids` | 创建 Read View 时所有活跃（未提交）事务的 ID 列表 |
| `min_trx_id` | `m_ids` 中的最小值 |
| `max_trx_id` | 下一个要分配的事务 ID（当前最大 ID + 1） |
| `creator_trx_id` | 创建此 Read View 的事务 ID |

### 可见性判断规则

1. `trx_id < min_trx_id` → **可见**（修改该记录的事务已提交）
2. `trx_id >= max_trx_id` → **不可见**（修改发生在 Read View 创建之后）
3. `min_trx_id <= trx_id < max_trx_id`：
   - 在 `m_ids` 中 → **不可见**（该事务仍活跃）
   - 不在 `m_ids` 中 → **可见**（该事务已提交）

### MVCC 实现可重复读

- 事务启动时创建 Read View，**整个事务期间不变**
- 即使其他事务修改并提交了数据，当前事务仍只读取 Read View 创建时的版本
- 保证事务内所有查询返回一致的数据状态

### MVCC 实现读提交

- 每次 SELECT **都创建新的 Read View**（与可重复读的核心区别）
- 事务总是看到最近提交的数据
- 同一事务内两次读取可能返回不同结果（因为 Read View 不同）

## 幻读

当同一个查询在不同时间产生不同的结果集时，就发生了幻读。例如 SELECT 执行两次，第二次返回了第一次没有的行。

### 触发幻读的场景

1. **通过 UPDATE 触发**：事务 A 查询范围内无记录，事务 B 插入一行并提交，事务 A 执行 UPDATE 更新该行后再次查询，突然"看到"了这行数据（UPDATE 是当前读，会读到最新版本）
2. **快照读与当前读混合使用**：先用普通 `SELECT`（快照读），再用 `SELECT ... FOR UPDATE`（当前读），两次结果集不同

### 快照读如何避免幻读

可重复读级别下，事务第一次查询时创建 Read View，后续所有查询都使用同一个 Read View。即使其他事务插入了新记录，通过 Read View + undo log 版本链也查询不到，从而避免幻读。

### 当前读如何避免幻读

MySQL 中 UPDATE、INSERT、DELETE 以及 `SELECT ... FOR UPDATE` 都是当前读，会读取最新版本。InnoDB 在可重复读级别下对当前读使用 **Next-Key Lock**（行锁 + 间隙锁），锁住记录本身和记录之间的间隙，阻止其他事务在该范围内插入新记录。

### InnoDB 可重复读是否完全解决了幻读

**不完全**。在以下场景仍可能出现幻读：
- 事务先执行快照读（不加锁），其他事务插入数据并提交，然后该事务执行当前读，就会看到新数据
- 解决方案：在事务开始时就使用 `SELECT ... FOR UPDATE` 加锁，而不是先快照读再当前读
