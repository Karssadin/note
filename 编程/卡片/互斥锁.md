互斥锁（Mutex，Mutual Exclusion）是保证多个线程对**共享资源互斥访问**的同步机制。同一时刻只有一个线程能持有锁，其他线程阻塞等待。

## 特性

- **互斥性**：同一时刻只有一个线程持锁
- **阻塞等待**：获取不到锁的线程进入睡眠（让出CPU），被唤醒后重新竞争
- **优点**：简单直观，适用于临界区保护
- **缺点**：可能导致线程等待，高频竞争时上下文切换开销大

## C++ 使用

### POSIX `pthread_mutex`

```cpp
pthread_mutex_t mtx = PTHREAD_MUTEX_INITIALIZER;
pthread_mutex_lock(&mtx);
// 临界区
pthread_mutex_unlock(&mtx);
```

### C++11 `std::mutex`

```cpp
#include <mutex>
std::mutex mtx;

void safeIncrement(int& counter) {
    std::lock_guard<std::mutex> lock(mtx);  // RAII 自动加/解锁
    ++counter;
}
```

## Go 使用

Go 中互斥锁由 `sync.Mutex` 提供，常用于保护共享状态：

```go
var mu sync.Mutex
var counter int

func inc() {
	mu.Lock()
	defer mu.Unlock()
	counter++
}
```

注意：

1. `sync.Mutex` 不可重入。
2. 不要复制已经使用过的锁，包含锁的结构体也应避免按值拷贝。
3. 临界区应尽量短；复杂共享状态用锁，简单计数可考虑 [[Go sync-atomic]]。

### 双重检查锁定（DCLP）

```cpp
std::mutex mtx;
std::atomic<Singleton*> instance{nullptr};

Singleton* getInstance() {
    if (!instance.load(std::memory_order_acquire)) {
        std::lock_guard<std::mutex> lock(mtx);
        if (!instance.load(std::memory_order_relaxed))
            instance.store(new Singleton(), std::memory_order_release);
    }
    return instance;
}
```

## 与其他同步原语的对比

| 机制 | 等待方式 | 适用场景 |
|------|----------|----------|
| 互斥锁 | 阻塞（睡眠） | 临界区较长 |
| 自旋锁 | 忙等（循环） | 临界区极短，不可睡眠（中断上下文） |
| 读写锁 | 阻塞 | 读多写少 |
| 条件变量 | 阻塞+通知 | 等待某条件成立 |

## 死锁预防

```cpp
// 方式1：始终以相同顺序加锁
// 方式2：std::lock 同时锁多个互斥量（无死锁）
std::lock(mtx1, mtx2);
std::lock_guard<std::mutex> lg1(mtx1, std::adopt_lock);
std::lock_guard<std::mutex> lg2(mtx2, std::adopt_lock);

// 方式3：C++17 scoped_lock
std::scoped_lock lock(mtx1, mtx2);
```
