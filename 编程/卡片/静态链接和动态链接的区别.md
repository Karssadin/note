## 链接（Linking）概述

链接是将多个目标文件（`.o`）和库文件合并为一个可执行文件的过程，分为**静态链接**和**动态链接**两种方式。

---

## 静态链接（Static Linking）

**原理**：编译时直接将库代码**拷贝**到可执行文件中。

**库文件格式**：
- Linux：`.a`（Archive，多个 `.o` 的集合）
- Windows：`.lib`

**流程**：
```
编译：source.cpp → source.o
静态链接：source.o + libfoo.a → 可执行文件（自包含）
```

**命令示例**：
```bash
# 创建静态库
ar rcs libfoo.a foo.o bar.o

# 链接静态库
g++ main.o -L. -lfoo -o app_static
```

**优点**：
- 可执行文件独立，无运行时依赖
- 运行速度略快（无动态链接开销）
- 便于部署和分发（单文件）

**缺点**：
- 可执行文件体积大
- 库更新后，所有程序需**重新链接编译**
- 多个程序使用同一库，磁盘/内存中存在多份副本

---

## 动态链接（Dynamic Linking）

**原理**：编译时只记录符号信息，**运行时由 OS 加载**动态库并映射到进程地址空间。

**库文件格式**：
- Linux：`.so`（Shared Object）
- Windows：`.dll`（Dynamic Link Library）+ `.lib`（导入库）

### 加载时动态链接（Load-time Dynamic Linking）

程序启动时，OS 的**动态链接器**（`ld-linux.so`）自动加载所需 `.so`：

```bash
# 创建动态库（-fPIC：位置无关代码）
g++ -fPIC -shared foo.cpp -o libfoo.so

# 链接动态库
g++ main.o -L. -lfoo -o app_dynamic

# 运行（需要 .so 在库路径中）
export LD_LIBRARY_PATH=.:$LD_LIBRARY_PATH
./app_dynamic
```

### 运行时动态链接（Runtime Dynamic Linking）

程序运行中按需手动加载库，更灵活（插件机制）：

```cpp
#include <dlfcn.h>

void* handle = dlopen("./libfoo.so", RTLD_LAZY);  // 按需加载
if (!handle) { std::cerr << dlerror(); return 1; }

// 获取函数指针
typedef void (*FuncType)();
FuncType func = (FuncType) dlsym(handle, "my_function");

func();               // 调用
dlclose(handle);      // 卸载
```

**优点**：
- 多个程序共享**同一份**库（内存中只有一份），节省资源
- 库更新后，程序不需重新编译（热修复）
- 程序体积小
- 支持插件机制（运行时加载/卸载）

**缺点**：
- 运行时需要库存在（依赖管理复杂）
- 首次加载有延迟
- 库版本不兼容可能导致问题（DLL Hell）

---

## 对比总结

| 维度 | 静态链接 | 动态链接 |
|------|---------|---------|
| 链接时机 | 编译时 | 运行时（加载或按需）|
| 库文件格式 | `.a` / `.lib` | `.so` / `.dll` |
| 可执行文件大小 | 大（包含库代码）| 小（仅记录符号）|
| 内存占用 | 多份副本 | 共享，节省内存 |
| 运行速度 | 略快 | 稍慢（间接调用）|
| 更新便利性 | 需重新编译 | 替换 `.so` 即可 |
| 部署依赖 | 无依赖 | 需要对应版本的 `.so` |
| 典型使用 | 嵌入式、工具链 | 系统库（libc）、插件 |

---

## 位置无关代码（PIC，Position Independent Code）

动态库必须使用 `-fPIC` 编译，生成**位置无关代码**：

- 动态库被加载到进程地址空间的**任意位置**（ASLR 随机化）
- PIC 通过**全局偏移表（GOT）**和**过程链接表（PLT）**实现符号重定位
- 不使用 PIC 的代码只能被加载到固定地址，无法共享
