操作系统通过 CPU 的**特权级**（Ring Level）将运行环境分为两种模式，实现对硬件的保护。

## 用户态（User Mode / Ring 3）

- 运行应用程序代码
- **不能**直接访问硬件、内核内存
- **不能**执行特权指令（如 `cli`、`sti`、`in`/`out`）
- 受虚拟内存保护，只能访问自身地址空间

## 内核态（Kernel Mode / Ring 0）

- 运行操作系统内核代码
- 可直接访问任意物理内存和硬件
- 可执行所有 CPU 指令
- 负责管理进程、内存、设备、文件系统等

## 切换时机

| 方向 | 触发条件 |
|------|----------|
| 用户态 → 内核态 | 系统调用、硬件中断、异常（缺页、除零等） |
| 内核态 → 用户态 | 系统调用返回、中断处理完毕 |

## 切换开销

切换过程需要：

1. 保存用户态 CPU 寄存器（通用寄存器、PC、SP 等）
2. 切换页表（用户空间 → 内核空间地址）
3. 刷新 TLB（部分架构）
4. 执行内核代码后，逆向恢复

**开销约 ~1μs～几十μs**，频繁切换（如高频系统调用）会严重影响性能。

## 系统调用

系统调用是用户程序请求内核服务的唯一合法途径：

```cpp
// 用户程序调用 write()
write(fd, buf, len);
// ↓ 库函数发起 syscall 指令
// ↓ CPU 切换到内核态
// ↓ 内核执行 sys_write()
// ↓ 返回用户态
```

## 降低切换开销的技术

| 技术 | 原理 |
|------|------|
| **vDSO / vsyscall** | 将部分系统调用（如 `gettimeofday`）映射到用户空间执行，避免切换 |
| **io_uring** | 批量 I/O 操作，减少 syscall 次数 |
| **DPDK / RDMA** | 用户态网络驱动，绕过内核 |
| **eBPF** | 在内核中执行用户定义的程序，减少数据拷贝 |
