- 行为型模式
- 定义：定义一系列算法，把他们一个个封装起来（接口调用不同算法），并且他们可以互相替换，该模式使得算法可独立于使用它的客户程序而变化

解决了什么问题？

- 稳定点：客户程序和算法的调用关系
- 变化点：新增算法、算法内容的变化、动态切换算法
- 将算法抽象继承自不同的接口
- **接口隔离原则**
- 尽量不要让用户选择不需要的接口
- 类与类的依赖建立在最基础的接口，而非派生类接口
- 使用接口指针采用具体接口选择算法
- 依赖注入

代码结构

- 商场促销活动

```C
//算法接口
class ProStategy{
public:
    virtual double CalcPro(const Context &ctx) = 0;
    virtual ~ProStategy();
};
//算法实现
class VAC_Spring : public ProStategy{
public:
    virtual double CalcPro(const Context &ctx){};
};
class VAC_Qixi : public ProStategy{
public:
    virtual double CalcPro(const Context &ctx){};
};
//接口隔离原则
class Promotion{
public:
    Promotion(Prostategy *sss = nullptr) : s(sss){}
    ~Promotion(){}

    //依赖注入
    void Choose(ProStategy *sss){
        if(sss != nullptr)
            s = sss;
    }
    double CalcPromotion(const Context &ctx){
        if(s != nullptr)
            return s->CalcPro(ctx);
        return 0.0L;
    }
private:
//算法接口指针实现接口隔离
    ProStategy *s;
}
int main(){
    Context ctx;
    ProStategy *s = new VAC_Qixi();
    Promotion *p = new Promotion(s);
    p->CalcPromotion(ctx);

    p->Choose(new VAC_Spring)
    return 0;
}
```
