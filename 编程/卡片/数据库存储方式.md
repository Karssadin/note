数据库的存储方式决定了数据在磁盘上的组织形式，直接影响查询性能和存储效率。

## 行存储（Row-oriented）

将一行的所有列连续存储在一起，适合 OLTP 场景。

- 优势：单行读写高效，事务处理友好
- 劣势：列分析型查询需要读取大量无关列
- 代表：MySQL InnoDB、PostgreSQL

## 列存储（Column-oriented）

将同一列的数据连续存储，适合 OLAP 场景。

- 优势：聚合查询只读需要的列，压缩率高
- 劣势：单行操作需要组装多列数据
- 代表：[[ClickHouse]]、[[StarRocks]]、[[duckDB]]

## 存储结构

| 结构 | 特点 | 应用 |
|------|------|------|
| 堆文件（Heap File） | 无序存储，插入快 | PostgreSQL 默认 |
| 有序文件 | 按键排序，范围查询高效 | 少见 |
| B+ 树 | 有序索引组织，读写平衡 | MySQL InnoDB |
| LSM Tree | 写优化，批量合并 | RocksDB、LevelDB |
| PAX（混合） | 页内按列组织 | 分析型数据库 |

## 页与块

数据库以**页**（Page，通常 4KB~16KB）为最小 I/O 单位。页内存放多条记录，通过槽目录（Slot Directory）管理变长记录的位置。
