## 什么是内存碎片

内存碎片是指内存中存在大量无法被有效利用的小块空闲空间。分为两类：

### 外部碎片（External Fragmentation）

- **定义**：空闲内存总量足够，但不连续，无法满足大块内存请求
- **产生原因**：频繁分配/释放不同大小的内存块后，空闲区被分割为很多小块
- **典型场景**：堆内存长时间运行后的状态

```
[已用 100B][空闲 10B][已用 200B][空闲 15B][已用 50B][空闲 8B]
→ 空闲总量 33B，但最大连续块只有 15B，无法分配 20B 的请求
```

### 内部碎片（Internal Fragmentation）

- **定义**：已分配给进程的内存中，实际使用量少于分配量，浪费在"内部"
- **产生原因**：内存分配粒度（如按页对齐、固定块大小）导致分配量大于实际需求
- **典型场景**：页式内存管理（最后一页可能只用了一半）

```
请求分配 33B → 系统按 64B 对齐分配 → 浪费 31B 的内部碎片
```

## 操作系统级解决方案

| 方案 | 说明 |
|------|------|
| **内存紧凑（Compaction）** | 移动已分配区域，合并空闲区（代价高，需停止进程） |
| **伙伴系统（Buddy System）** | 按 2 的幂次分配，分裂/合并时保持对齐，减少外部碎片 |
| **分页（Paging）** | 固定大小页框，消除外部碎片（但有内部碎片） |
| **分段+分页（Segmentation+Paging）** | 结合两者优点 |

## 应用层解决方案

### 1. 内存池（Memory Pool）

预先分配一大块内存，按需从中划分固定大小的块：

```cpp
class MemoryPool {
    static const int BLOCK_SIZE = 64;
    static const int POOL_SIZE = 1024;
    char pool[POOL_SIZE * BLOCK_SIZE];
    bool used[POOL_SIZE];
public:
    void* alloc() {
        for (int i = 0; i < POOL_SIZE; i++)
            if (!used[i]) { used[i] = true; return pool + i * BLOCK_SIZE; }
        return nullptr;
    }
    void free(void* ptr) {
        int i = ((char*)ptr - pool) / BLOCK_SIZE;
        used[i] = false;
    }
};
```

**优点**：消除外部碎片、分配速度快（O(1)）、避免频繁系统调用

### 2. 对象池 / Slab 分配器

Linux 内核使用的 Slab 分配器：对同一类型的对象维护一个缓存池，避免重复构造/析构和碎片。

### 3. 自定义 allocator（STL 场景）

```cpp
std::vector<int, PoolAllocator<int>> vec;
```

### 4. jemalloc / tcmalloc

用于替换系统 malloc，通过多级缓存和尺寸分类减少碎片：
- **tcmalloc**（Google）：线程本地缓存减少锁竞争
- **jemalloc**（Facebook/Firefox）：arena 机制减少碎片，统计分析友好

## 碎片对性能的影响

1. **内存利用率下降**：有效内存减少，导致更早触发 OOM
2. **分配速度变慢**：搜索合适空闲块时间增加（`malloc` 的 first-fit/best-fit）
3. **Cache 命中率下降**：碎片化的内存分配导致数据局部性差

## 与 C++ 的关联

```cpp
// 长时间运行的服务中，频繁 new/delete 小对象会产生外部碎片
for (int i = 0; i < 1000000; i++) {
    auto* p = new SmallObj();  // 可能大量外部碎片
    delete p;
}

// 解决：使用对象池
SmallObjPool pool;
for (int i = 0; i < 1000000; i++) {
    auto* p = pool.alloc();
    pool.free(p);
}
```
