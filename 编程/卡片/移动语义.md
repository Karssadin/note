## 移动语义（Move Semantics）

移动语义是 C++11 引入的核心特性，通过**转移资源所有权**来消除不必要的深拷贝，显著提升性能。

## 问题背景

传统拷贝构造函数会深拷贝堆内存，对于临时对象（右值）这种拷贝完全浪费：

```cpp
std::string a = "hello";
std::string b = a;          // 拷贝构造：深拷贝，分配新内存
std::string c = a + "world"; // 拷贝构造：a+"world" 是临时量，拷贝后临时量销毁 → 浪费
```

## 移动构造函数与移动赋值运算符

```cpp
class MyString {
    char* data;
    size_t size;
public:
    // 移动构造：窃取资源，将 other 置为空
    MyString(MyString&& other) noexcept
        : data(other.data), size(other.size) {
        other.data = nullptr;
        other.size = 0;
    }

    // 移动赋值
    MyString& operator=(MyString&& other) noexcept {
        if (this != &other) {
            delete[] data;
            data = other.data;
            size = other.size;
            other.data = nullptr;
            other.size = 0;
        }
        return *this;
    }
};
```

## std::move

`std::move` 将左值**强制转换**为右值引用，触发移动语义（它本身不做任何移动）：

```cpp
std::vector<int> v1 = {1, 2, 3};
std::vector<int> v2 = std::move(v1);  // v1 的资源转移给 v2
// v1 现在为空（有效但未指定状态）
```

**注意**：`std::move` 后不应再使用 `v1`（除非重新赋值）。

## 触发移动的场景

1. 函数返回局部变量（RVO/NRVO，编译器通常会优化）
2. 将临时对象（右值）传递给接受右值引用的函数
3. 显式使用 `std::move`

## 对基本类型的效果

基本类型（`int`、`double`）没有移动构造，`std::move` 对它们仍然是复制，无性能提升。移动语义对**含堆资源**的对象才有意义（`std::string`、`std::vector`、`std::unique_ptr` 等）。

## noexcept 的重要性

移动构造/赋值应标记 `noexcept`：
- STL 容器（如 `std::vector`）在扩容时，若移动构造不是 `noexcept`，会回退到拷贝（为保证异常安全）
- 标记 `noexcept` 可让 `std::vector` 真正使用移动而非拷贝，带来性能提升

## 与拷贝构造的对比

| 操作 | 行为 | 时间复杂度 |
|------|------|---------|
| 拷贝构造 | 分配新内存，逐元素拷贝 | O(n) |
| 移动构造 | 转移指针，置空源对象 | O(1) |
