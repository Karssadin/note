## 什么是设计模式

在软件开发中，用于解决特定环境下重复出现的特定问题的解决方案。

**设计模式解决了什么问题？**
- 分析需求的**稳定点**和**变化点**：稳定点保持不变，变化点用模式封装
- 期望修改少量代码可以适应需求变化（开闭原则）
- 慎用设计模式：不要为了用而用

## 六大设计原则（SOLID）

| 原则 | 说明 |
|------|------|
| **单一职责**（SRP） | 一个类只做一件事 |
| **开闭原则**（OCP） | 对扩展开放，对修改封闭 |
| **里氏替换**（LSP） | 子类可以替换父类 |
| **接口隔离**（ISP） | 依赖最小接口，不强迫实现不需要的方法 |
| **依赖倒置**（DIP） | 依赖抽象，不依赖具体实现 |
| **迪米特法则**（LoD） | 最少知识原则，减少耦合 |

## 分类

### 创建型（对象的创建）

- [[单例模式]]：确保类只有一个实例，全局访问点
- [[工厂模式]]：简单工厂 / 工厂方法 / 抽象工厂，将创建与使用分离
- [[建造者模式]]：分步构建复杂对象，解决构造函数参数过多问题

### 结构型（类/对象的组合）

- [[代理模式]]：控制对对象的访问（延迟加载、权限、RPC）
- [[装饰器模式]]：动态增加功能，比继承更灵活
- [[适配器模式]]：接口转换，让不兼容的类协同工作

### 行为型（对象间的通信）

- [[策略模式]]：封装算法族，运行时切换，避免 if-else 条件判断
- [[观察者模式]]：一对多依赖，状态变化时自动通知所有观察者
- [[责任链模式]]：请求沿链传递，解耦发送者与接收者
- [[模板方法模式]]：骨架在基类，步骤延迟到子类实现

- 策略模式 vs 模板方法？
