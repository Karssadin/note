行为型模式。在基类中定义算法的**骨架**，将某些步骤延迟到子类实现。子类可以重写特定步骤，但不能改变整体结构。

## 解决了什么问题

- **稳定点**：算法的整体流程（骨架）
- **变化点**：流程中某些具体步骤的实现

## 代码示例（数据挖掘报告）

```cpp
class DataMiner {
public:
    // 模板方法：定义算法骨架（final 防止子类重写）
    void mine(const string& path) {
        openFile(path);
        extractData();
        parseData();
        analyzeData();
        sendReport();
        closeFile();
    }

protected:
    virtual void openFile(const string& path) { /* 默认实现 */ }
    virtual void closeFile() { /* 默认实现 */ }
    virtual void extractData() = 0;  // 纯虚，子类必须实现
    virtual void parseData() = 0;
    virtual void analyzeData() { /* 默认实现，子类可覆盖 */ }

private:
    void sendReport() { /* 固定步骤，不允许子类修改 */ }
};

class PDFMiner : public DataMiner {
    void extractData() override { /* 从PDF提取 */ }
    void parseData() override   { /* 解析PDF格式 */ }
};

class CSVMiner : public DataMiner {
    void extractData() override { /* 从CSV提取 */ }
    void parseData() override   { /* 解析CSV格式 */ }
};
```

## 钩子（Hook）

可选步骤，在基类中提供空实现，子类可选择性覆盖：

```cpp
virtual bool shouldSendReport() { return true; }  // Hook
void mine(const string& path) {
    // ...
    if (shouldSendReport()) sendReport();
}
```

## 与策略模式的区别

| 维度 | 模板方法 | 策略模式 |
|------|----------|----------|
| 机制 | 继承 | 组合 |
| 变化粒度 | 算法中的某个步骤 | 整个算法 |
| 运行时切换 | 不可以 | 可以 |

## 应用案例

- **测试框架**：JUnit 的 `setUp → test → tearDown`
- **HTTP 框架**：模板定义请求处理流程，子类实现具体 handler
- **数据库 ORM**：基类定义 CRUD 框架，子类实现 SQL 差异
