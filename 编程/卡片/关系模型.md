## 关系模型的诞生

Ted Codd 于 1970 年提出关系模型，解决了早期 DBMS 逻辑层与物理层耦合的问题：

- **以关系（表）存储数据**：所有数据用表（relation）的形式组织
- **高级语言访问**：只描述"想要什么数据"，不描述"如何获取"（声明式）
- **逻辑层与物理层解耦**：修改物理存储方式不影响上层查询

## 数据模型分类

| 类型 | 代表系统 |
|------|---------|
| **Relational**（关系型） | MySQL、PostgreSQL、Oracle |
| **Key/Value** | Redis、DynamoDB |
| **Document** | MongoDB |
| **Graph** | Neo4j |
| **Column-family** | Cassandra、RocksDB |
| **Array/Matrix** | 机器学习专用（TensorFlow Dataset） |
| **Hierarchical/Network**（历史遗留） | IMS、IDMS |

## 关系模型三要素

1. **关系结构（Structure）**：定义关系（表）的属性（列）和可取的值（域）
2. **数据完整性（Integrity）**：确保数据满足约束条件
3. **操作（Manipulation）**：定义如何访问和修改数据（关系代数 / SQL）

## 关键概念

- **模式（Schema）**：在给定数据模型下对特定数据集合的描述（即表定义）
- **关系（Relation）**：即表，是一个 n 元元组的集合
- **元组（Tuple）**：表中的一行，各属性的值的集合
- **属性（Attribute）**：表中的列，有名称和类型
- **域（Domain）**：属性可取的合法值集合

## 数据完整性约束

- **实体完整性**：主键（Primary Key）不能为 NULL，且在关系内唯一
- **参照完整性**：外键（Foreign Key）值要么为 NULL，要么在被引用关系中存在
- **用户定义完整性**：CHECK 约束、NOT NULL、UNIQUE 等业务规则

## 值的规范

- **原子值（Atomic Values）**：每个字段的值是不可再分的基本数据单位（第一范式要求）
- **标量值（Scalar Values）**：每个字段存储单一简单值，不是集合或结构

## 数据操作语言

| 语言 | 缩写 | 功能 |
|------|------|------|
| Data Manipulation Language | DML | 增删改查（SELECT/INSERT/UPDATE/DELETE） |
| Data Definition Language | DDL | 定义表结构（CREATE/ALTER/DROP） |
| Data Control Language | DCL | 权限控制（GRANT/REVOKE） |

DML 分为：
- **Procedural**（过程式）：关系代数（Relational Algebra）
- **Non-Procedural**（声明式）：关系演算（Relational Calculus）、SQL

## NoSQL 简介

NoSQL（Not Only SQL）：
- 不使用关系模型，或不完全遵循 ACID
- 适合半结构化/非结构化数据、水平扩展、高吞吐量
- 例：键值（Redis）、文档（MongoDB）、列存（Cassandra）、图（Neo4j）
