| 维度 | map | unordered_map |
|------|-----|---------------|
| 底层 | 红黑树 | 哈希表 |
| 元素顺序 | 按 key 有序 | 无序 |
| 查找复杂度 | O(log n) | 平均 O(1)，最坏 O(n) |
| 插入/删除 | O(log n) | 平均 O(1) |
| 迭代器稳定性 | 插入删除不影响其他迭代器 | rehash 时所有迭代器失效 |
| 自定义 key 要求 | 需要 `<` 运算符 | 需要 hash 函数和 `==` 运算符 |
| 内存 | 树节点开销 | 哈希桶 + 链表/开放寻址开销 |
| 适用场景 | 需要有序、范围查询 | 只需快速查找、无序 |

## map 中 find 和 [] 的区别

- `[]`：如果 key 不存在，会自动插入一个默认值
- `find()`：key 不存在返回 `end()` 迭代器，不会插入

## 为什么 map/set 用红黑树不用 AVL 树

- AVL 树每次插入删除可能需多次旋转，红黑树最多 3 次
- 红黑树平衡条件宽松，写操作常数因子更小
- 红黑树只需 1 bit 存颜色，AVL 需存高度差
- 两者查找都是 O(log n)，读性能接近

## 扩容因子

- 成倍扩容保证均摊 O(1)，固定增量只能 O(n)
- GCC 用 2 倍，MSVC 用 1.5 倍
- 1.5 倍可复用之前释放的内存（对缓存更友好）
