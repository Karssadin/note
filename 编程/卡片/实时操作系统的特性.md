## 实时操作系统（RTOS）

**定义**：能在**确定的时间限制**内对外部事件做出响应的操作系统，核心特性是**时间确定性**（Determinism）。

---

## 硬实时 vs 软实时

| 特性 | 硬实时（Hard Real-Time）| 软实时（Soft Real-Time）|
|------|----------------------|----------------------|
| 截止时间 | 绝对不能错过，错过=系统失败 | 偶尔错过可接受，但影响体验 |
| 超时后果 | 灾难性（飞机坠毁/核电站事故）| 性能下降，不会危及安全 |
| 典型场景 | 航空航天、工业控制、医疗设备 | 视频流媒体、音频播放、游戏 |
| 典型系统 | VxWorks、FreeRTOS | Linux（PREEMPT_RT 补丁）|

---

## 核心特性

### 1. 抢占式调度（Preemptive Scheduling）

高优先级任务**可随时抢占**低优先级任务的 CPU，确保紧急任务立即响应：

```
优先级：任务H（高）> 任务M（中）> 任务L（低）

事件到来时：
任务L 正在运行
→ 任务H 就绪
→ 立即抢占 L，执行 H
→ H 完成后，恢复 L
```

### 2. 确定性调度延迟

系统最大调度延迟（Scheduling Latency）固定且可预测，通常为微秒级（μs）：
- Linux 通用：调度延迟可能达到毫秒（ms）级
- RTOS：通常 < 10μs

### 3. 时间分区与隔离

各任务在时间上隔离，防止低优先级任务阻塞高优先级任务。使用**中断屏蔽**控制临界区，最短化屏蔽时间。

### 4. 优先级继承

RTOS 内置**优先级继承**（Priority Inheritance）解决优先级反转问题，确保高优先级任务等待时间有界。

详见 [[优先级反转概念及解决思路]]

## 与分时操作系统对比

| 维度 | 实时 OS（RTOS）| 分时 OS（GPOS）|
|------|--------------|--------------|
| 调度目标 | 确定性响应时间 | 公平分配 CPU 时间 |
| 中断延迟 | 微秒级，确定 | 毫秒级，不确定 |
| 用户数量 | 通常单用户/单任务 | 多用户/多任务 |
| 资源管理 | 静态预分配 | 动态分配 |
| 代表系统 | FreeRTOS、VxWorks、RT-Thread | Linux、Windows |

## 典型 RTOS 代表

| 系统 | 特点 | 应用场景 |
|------|------|---------|
| **FreeRTOS** | 开源、轻量（<10KB）、跨平台 | 嵌入式（STM32、ESP32）|
| **VxWorks** | 商业级、高可靠、DO-178B 认证 | 航空航天、军事 |
| **RT-Thread** | 国产开源、丰富生态 | IoT 设备 |
| **Zephyr** | Linux 基金会支持 | IoT、穿戴设备 |
| **Linux + PREEMPT_RT** | 实时补丁，软实时 | 工业控制、机器人 |

## 操作系统功能（五大管理）

| 功能 | 说明 |
|------|------|
| **处理器管理** | 进程/线程调度，CPU 分配 |
| **存储器管理** | 物理/虚拟内存分配，缺页中断 |
| **设备管理** | 设备驱动，I/O 调度 |
| **文件管理** | 文件系统，目录、权限、I/O |
| **用户接口** | Shell、GUI、系统调用接口 |
