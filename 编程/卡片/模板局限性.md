## 模板的局限性与使用注意事项

### 局限性

**1. 不适用于所有类型**

模板并非万能，某些自定义类型（类、对象）在执行模板运算时，可能因**运算符不匹配**而失败：

```cpp
template<typename T>
bool myCompare(T a, T b) { return a == b; }

struct Person { std::string name; int age; };
Person p1{"Alice", 20}, p2{"Alice", 20};
myCompare(p1, p2);  // 编译错误：Person 未定义 operator==
```

**解决方案**：
- 为自定义类型重载所需运算符
- 使用**具体化模板**（Template Specialization）对特定类型单独实现：

```cpp
template<>
bool myCompare<Person>(Person& p1, Person& p2) {
    return p1.name == p2.name && p1.age == p2.age;
}
```

**2. 类型推导要求一致**

自动类型推导时，所有同一模板参数 T 对应的实参必须推导为**相同类型**：

```cpp
template<typename T>
T add(T a, T b) { return a + b; }

add(1, 2);       // OK：T=int
add(1, 2.0);     // 错误：T 无法同时推导为 int 和 double
add<double>(1, 2.0);  // OK：显式指定 T=double
```

**3. 必须确定 T 的类型**

模板实例化时，T 必须能被推导或显式指定，否则编译报错：

```cpp
template<typename T>
void func() { T x; }   // T 无法从函数参数推导

func();            // 错误
func<int>();       // OK
```

**4. 定义不能分离到 .cpp 文件**

模板定义（实现）必须在头文件（`.h`）中，不能将声明放 `.h`、实现放 `.cpp`：

原因：模板的实例化发生在**编译期**，编译器在每个使用模板的翻译单元中都需要看到完整的模板定义。

```cpp
// ✅ 正确：在 .h 中同时声明和定义
template<typename T>
T max(T a, T b) { return a > b ? a : b; }

// ❌ 错误：.h 只声明，.cpp 中定义 → 链接时找不到实例
```

### 使用注意事项

| 注意点 | 说明 |
|--------|------|
| 避免代码膨胀 | 每种类型实例化一份代码，类型数量多时二进制体积增大 |
| 编译期成本 | 复杂模板（如 TMP）会显著增加编译时间 |
| 错误信息难读 | 模板实例化失败时，错误信息通常很长、难以理解 |
| 使用 `concept`（C++20）| 用约束代替 SFINAE，显著改善错误信息可读性 |
| 优先使用 `if constexpr` | 编译期分支，比 SFINAE 更直观 |
