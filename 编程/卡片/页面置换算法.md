当物理内存不足，需要将某个内存页换出到磁盘时，**页面置换算法**决定淘汰哪个页面。

## 四种常见算法

### 1. FIFO（先进先出）

淘汰最早调入内存的页面。

- **实现**：用队列维护，队首为最早进入的页面
- **优点**：实现简单
- **缺点**：
  - 可能淘汰频繁使用的页面
  - 存在 **Belady 异常**：分配更多物理帧可能导致缺页次数**反而增加**

```
访问序列：1 2 3 4 1 2 5 1 2 3 4 5
3帧 FIFO 缺页数：9
4帧 FIFO 缺页数：10  ← Belady 异常！
```

### 2. OPT（最佳置换算法）

淘汰**未来最长时间内不会被访问**的页面。

- **优点**：缺页次数最少，理论最优
- **缺点**：需要预知未来，**无法实际实现**，只作为理论基准
- **不存在 Belady 异常**

### 3. LRU（最近最久未使用）

淘汰**最长时间未被访问**的页面（基于局部性原理）。

- **优点**：接近 OPT，性能好；**不存在 Belady 异常**
- **缺点**：实现复杂，精确实现需要时间戳或链表

**LRU 的精确实现（哈希表 + 双向链表）：**

```cpp
class LRUCache {
    int capacity;
    list<pair<int,int>> cache;          // {key, value}，链表头为最近使用
    unordered_map<int, list<pair<int,int>>::iterator> mp;  // key -> 迭代器

public:
    LRUCache(int cap) : capacity(cap) {}

    int get(int key) {
        if (!mp.count(key)) return -1;
        // 移到链表头（最近使用）
        cache.splice(cache.begin(), cache, mp[key]);
        return mp[key]->second;
    }

    void put(int key, int value) {
        if (mp.count(key)) {
            cache.erase(mp[key]);
            mp.erase(key);
        }
        if ((int)cache.size() == capacity) {
            // 淘汰链表尾部（最久未使用）
            mp.erase(cache.back().first);
            cache.pop_back();
        }
        cache.push_front({key, value});
        mp[key] = cache.begin();
    }
};
```

**复杂度：** get/put 均 O(1)

**LRU 的近似实现（时间戳）：** 每次访问记录时间戳，淘汰时选时间戳最小的；实现简单但开销大。

### 4. Clock（时钟置换 / NRU）

为每个页面维护一个**访问位（R bit）**，形成循环队列：

- 访问页面时将 R 置 1
- 置换时：顺时针扫描，遇到 R=0 则淘汰；遇到 R=1 则将其置 0 并继续扫描
- **优点**：近似 LRU，实现简单（操作系统实际广泛使用）

**Clock 的改进（Second Chance / Enhanced Clock）：**
使用 (R, M) 两位标志（R=访问位，M=修改脏位），优先淘汰 (0,0)（未用未改），避免淘汰已修改的页面（需写回磁盘代价高）。

## 算法对比

| 算法 | 实现难度 | 性能 | Belady 异常 | 特点 |
|------|---------|------|-------------|------|
| FIFO | 简单 | 差 | **存在** | 队列维护 |
| OPT | 无法实现 | 最优 | 不存在 | 理论基准 |
| LRU | 复杂（哈希+链表） | 接近最优 | 不存在 | 工业常用 |
| Clock | 简单 | 较好 | 不存在 | OS 实际使用 |

## Belady 异常

**定义**：某些置换算法（FIFO）在增加物理帧数量时，缺页次数**不减反增**的现象。

**根本原因**：FIFO 不是**栈算法**（Stack Algorithm）。栈算法满足：n 帧的命中集合是 n+1 帧命中集合的子集，LRU 和 OPT 都是栈算法（无 Belady 异常），FIFO 不是。

## 换出页面保存位置

被换出的页面保存在**磁盘的对换区（Swap Space）**：
- 磁盘分为文件区（离散分配）和**对换区（连续分配，速度快）**
- 对换区 I/O 速度比文件区快，以减少换入换出延迟

## 与 MySQL Buffer Pool 的关联

MySQL Buffer Pool 的 LRU 淘汰策略本质上是页面置换算法的应用：
- 改进的 LRU（Young + Old 区），新页先进 Old 区，访问后才升入 Young 区
- 避免全表扫描时大量冷数据刷走热数据（类似 OPT 的预测思想）
