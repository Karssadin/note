## 核心区别对比

| 维度 | 分段（Segmentation） | 分页（Paging） |
|------|---------------------|--------------|
| 划分单位 | 逻辑单位（代码段、数据段、栈段） | 物理单位（固定大小页，如 4KB） |
| 大小 | 不固定，由程序结构决定 | 固定（4KB / 8KB） |
| 地址维度 | 二维（段号 + 段内偏移） | 一维（线性地址） |
| 碎片类型 | 外部碎片（段大小不固定） | 内部碎片（最后一页可能浪费） |
| 对用户的可见性 | 可见（程序员感知段） | 透明（对程序员隐藏） |
| 保护与共享 | 段级保护（代码只读、数据读写）；段可共享 | 页级保护；共享粒度较粗 |
| 管理目的 | 满足逻辑结构需求 | 简化物理内存管理，消除外部碎片 |

## 分页详解

### 地址转换
```
虚拟地址 = 页号（VPN）+ 页内偏移（Offset）
物理地址 = 页表[VPN].PFN + Offset
```

### TLB（快表）加速
每次地址转换需访问内存中的页表，代价高。TLB（Translation Lookaside Buffer）是 MMU 内部的硬件缓存：
- TLB 命中（~1 cycle）：直接得到物理地址
- TLB 缺失：访问内存页表 → 回填 TLB
- TLB 命中率通常 > 99%（局部性原理）

### 多级页表
64 位系统地址空间巨大，单级页表占用内存过多，采用多级页表（x86_64 四级：PGD/PUD/PMD/PTE）：
- **节省内存**：只有实际使用的区域才分配下级页表
- **代价**：地址转换需多次内存访问（TLB 可缓解）

## 分段详解

### 地址转换
```
逻辑地址 = <段号 S, 段内偏移 d>
物理地址 = 段表[S].base + d  （需验证 d < 段表[S].limit）
```

### 段级保护
每个段表项包含权限位（R/W/X），硬件强制检查，违规触发段错误（Segmentation Fault）。

---

## 段页式（现代 OS 实际使用）

结合两者优势：
1. 程序按**段**划分逻辑结构（代码/数据/栈）
2. 每个段内部按**页**管理物理内存

地址转换流程：
```
逻辑地址 → 段号 → 段描述符（段基址） → 线性地址
线性地址 → 多级页表 → 物理地址
```

- **x86 保护模式**即使用段页式（段选择子 + 偏移 → 线性地址 → 页表 → 物理地址）
- Linux 几乎不使用分段（段基址均设为 0），实际退化为纯分页

---

## 常考面试点

1. **段错误（Segmentation Fault）** 是分段保护机制检测到非法访问时的报错，与缺页中断不同
2. **页大小的权衡**：大页减少 TLB 缺失，但内部碎片大；小页碎片小，但页表大
3. **Huge Pages**：Linux 支持 2MB/1GB 大页，减少 TLB 缺失，适合数据库/JVM 大内存场景
