## TLS 握手阶段

1. **TCP 连接建立**：浏览器与服务器在端口 443 完成三次握手
2. **ClientHello**：客户端发送支持的 TLS 版本、加密套件列表、随机数
3. **ServerHello**：服务端选定 TLS 版本和加密套件，发送随机数 + 数字证书（含公钥）
4. **证书验证**：客户端验证证书有效性（CA 签名、有效期、域名匹配）
5. **密钥交换**：
   - RSA：客户端生成预主密钥，用服务端公钥加密发送
   - ECDHE：双方各生成临时密钥对，通过 DH 算法协商预主密钥（提供前向安全）
6. **会话密钥生成**：双方用预主密钥 + 两个随机数生成**对称会话密钥**
7. **握手确认**：双方发送 Finished 消息，用会话密钥加密验证握手完整性

## 数据传输阶段

握手完成后，所有 HTTP 数据用**对称密钥（AES 等）加密**传输：

- 请求：浏览器加密 HTTP 请求 → 发送到服务器
- 处理：服务器用会话密钥解密 → 处理请求 → 加密响应
- 响应：浏览器解密响应 → 渲染内容

## TLS 1.2 vs TLS 1.3

| 维度 | TLS 1.2 | TLS 1.3 |
|------|---------|---------|
| 握手往返 | 2-RTT | 1-RTT（首次），0-RTT（恢复） |
| 密钥交换 | RSA 或 ECDHE | 强制 ECDHE（前向安全） |
| 过期算法 | 支持 RC4、SHA-1 等 | 全部移除 |
| 安全性 | 较高 | 更高 |

## 非对称加密 vs 对称加密用途

- **握手阶段**：非对称加密（RSA/ECDHE）用于安全传递密钥
- **数据传输**：对称加密（AES-GCM 等）用于高效加密数据
