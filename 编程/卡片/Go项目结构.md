# Go项目结构

Go 项目结构应优先保持简单，目录划分服务于包边界和依赖方向。

## 常见目录

1. `cmd/`：可执行程序入口。
2. `internal/`：只允许父目录树内代码导入的内部包。
3. `pkg/`：可被外部复用的库包，非必须。
4. `api/`：协议、接口定义或 OpenAPI 文件。
5. `configs/`：配置样例。
6. `scripts/`：构建、部署和辅助脚本。

## 原则

1. 不要过早创建复杂分层。
2. 包名应短小并表达职责。
3. 避免循环依赖。
4. main 包保持薄，业务逻辑放入可测试包。
