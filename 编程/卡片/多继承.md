- 多继承的复杂性
    - 增加程序编写和维护的难度，易于出错。
    - 在继承中可能出现成员同名，导致访问的不确定性（同名二义性）。
    - 解决方法包括**使用作用域运算符**`**::**`**指定基类成员**，或**在派生类中定义同名成员覆盖基类成员**。
- 路径二义性：
    - 当派生类从多个基类派生，且这些基类有共同的基类时，可能产生路径二义性。
    - 可通过上述方法解决同名二义性。
- 菱形继承：
    - 两个派生类继承同一个基类、又有某个类同时继承者两个派生类、这种继承被称为菱形继承，或者钻石继承
    - 虚继承用于解决菱形继承问题（Diamond Problem），即减少存储空间浪费和消除二义性。
    - 虚基类在子类中只会有一份拷贝。底层通过虚基类指针（vbptr）和虚基类表（virtual base table）实现。虚基类表存储的是虚基类相对直接继承类的偏移量。
    - **利用虚继承可以解决菱形继承的问题，在继承同一个基类时候，添加virtual，变成虚继承，对应的为虚基类**

## 虚继承内存布局

虚继承通过 **虚基类指针（vbptr）** 和 **虚基类表（vbtable）** 实现：

```cpp
class A { public: int a; };
class B : virtual public A { public: int b; };
class C : virtual public A { public: int c; };
class D : public B, public C { public: int d; };

// D 的内存布局：
// [B::vbptr] [B::b] [C::vbptr] [C::c] [D::d] [A::a（唯一共享）]
// vbtable 存储的是虚基类相对于当前子对象的偏移量，而非虚函数地址
```

**注意**：虚基类表（vbtable）存储的是**偏移量**，用于定位共享的基类子对象；而虚函数表（vtable）存储的是**虚函数地址**，两者是完全不同的机制。

```cpp
D d;
A* a = &d;  // 只有一份 A 的数据，无二义性
d.a = 10;   // OK，通过虚继承消除了菱形继承导致的二义性
```
