## 链接时"未定义的引用"（undefined reference）

### 常见原因

1. **缺少 .o 文件或库**：编译时没有链接对应的目标文件

```bash
# 错误示例
g++ main.cpp -o main
# /usr/bin/ld: undefined reference to `foo()'

# 正确：补充 foo.cpp 编译结果
g++ main.cpp foo.cpp -o main
# 或先编译为 .o 再链接
g++ -c main.cpp -o main.o
g++ -c foo.cpp  -o foo.o
g++ main.o foo.o -o main
```

2. **缺少第三方库**：头文件已包含，但链接阶段没有 `-l`

```bash
g++ main.cpp -o main -lpthread -lssl -lcrypto
```

3. **库的声明与定义不匹配**（C vs C++ 链接约定）

```cpp
// C 库头文件未加 extern "C"，C++ 会 mangle 函数名
extern "C" {
    #include "c_library.h"
}
```

4. **模板定义放在 .cpp 文件**：模板必须在头文件中定义

```cpp
// 错误：模板定义在 .cpp，其他 .cpp 无法实例化
// 正确：将模板定义放在 .h / .hpp 中
```

5. **循环依赖链接顺序问题（静态库）**

```bash
# GCC 静态库链接顺序：被依赖的库放后面
g++ main.o -lA -lB   # 若 A 依赖 B，此顺序正确
# 若出现循环依赖，用 --start-group/--end-group
g++ main.o -Wl,--start-group -lA -lB -Wl,--end-group
```

### 排查步骤

1. 报错信息中找到缺失的符号名
2. 用 `nm` 或 `objdump -t` 查找符号在哪个 .o/.a 文件
3. 用 `c++filt` 解码 mangled name：`c++filt _ZN3foo3barEv`
4. 确认编译命令中是否包含对应文件/库
