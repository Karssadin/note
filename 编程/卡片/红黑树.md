红黑树是一种**自平衡二叉查找树**，通过节点着色和旋转规则保证树的高度不超过 2log(n+1)，确保查找、插入、删除均为 O(log n)。

## 五条性质

1. 每个节点要么是红色，要么是黑色
2. 根节点是黑色
3. 所有叶节点（NIL 哨兵节点）是黑色
4. 红色节点的两个子节点必须是黑色（不能有两个连续的红节点）
5. 从任意节点到其所有后代叶节点的路径上，黑色节点数量相同（黑高相同）

性质 4 + 5 共同保证：最长路径（红黑交替）不超过最短路径（全黑）的 2 倍。

## 插入与删除要点

- 新插入的节点默认为**红色**（不违反性质 5，可能违反性质 4）
- 修复策略：根据叔节点颜色决定**变色**还是**旋转**
- 插入最多需要 2 次旋转 + 若干次变色
- 删除最多需要 3 次旋转 + 若干次变色

## 与 AVL 树对比

| 维度 | 红黑树 | AVL 树 |
|------|--------|--------|
| 平衡条件 | 黑高相同（宽松） | 左右子树高度差 <= 1（严格） |
| 查找 | O(log n)，常数略大 | O(log n)，常数更小 |
| 插入旋转 | 最多 2 次 | 最多 2 次 |
| 删除旋转 | 最多 3 次 | 可能 O(log n) 次 |
| 额外存储 | 1 bit（颜色） | 需存储高度/平衡因子 |
| 适用场景 | 写多读少（map/set） | 读多写少（数据库索引） |

## 在 STL 中的应用

- `std::map` / `std::multimap`：以红黑树为底层，按 key 有序
- `std::set` / `std::multiset`：以红黑树为底层，元素自动排序
- 选择红黑树而非 AVL 的原因：删除操作旋转次数更少，综合读写性能更均衡
