---

- C11之前指针管理的困境
    - 资源释放，指针没有置空：野指针（指针指向已经释放的内存）、悬挂指针（多个指针指向同一个内存，其中一个进行了释放）、踩内存（修改已经释放的内存）。
    - 没有释放资源，导致内存泄漏。忘记delte、delete之前return、delete抛出异常
    - 重复释放资源，引发coredump。多次释放资源
- 如何解决困境
    - RAII类模型，利用对象生命周期来控制资源，用于动态分配内存，其设计思想是将基本类型指针封装为（模板）类对象指针，并在离开作用域时调用析构函数，使用delete删除指针所指向的内存空间。

---

- 智能指针是为了解决动态分配内存导致内存泄露和多次释放同一内存所提出的，C11标准中放在`<memory>`头文件。包括auto_ptr，shared_ptr，unique_ptr，weak_ptr
- 智能指针的作用是，能够处理内存泄漏问题和空悬指针问题。

### auto_ptr

- 实现独占式拥有的概念，同一时间只能有一个智能指针可以指向该对象；auto_ptr在C++11中被摒弃，其主要问题在于：
    - 对象所有权的转移，比如在函数传参过程中，对象所有权不会返还，从而存在潜在的内存崩溃问题；
    - 不能指向数组，也不能作为STL容器的成员，析构调用delete

### unique_ptr

> 手撕unique_ptr

```C
template <typename T>
class unique_ptr {
private:
    T* ptr;
public:
    // 构造函数
    explicit unique_ptr(T* p = nullptr) : ptr(p) {}
    // 删除拷贝构造函数和拷贝赋值运算符
    unique_ptr(const unique_ptr&) = delete;
    unique_ptr& operator=(const unique_ptr&) = delete;
    // 移动构造函数
    unique_ptr(unique_ptr&& other) : ptr(other.ptr) {
        other.ptr = nullptr;
    }
    // 移动赋值运算符
    unique_ptr& operator=(unique_ptr&& other) {
        if (this != &other) {
            delete ptr;
            ptr = other.ptr;
            other.ptr = nullptr;
        }
        return *this;
    }
    // 析构函数
    ~unique_ptr() {
        delete ptr;
    }
    // 重载 * 和 -> 运算符
    T& operator*() const {
        return *ptr;
    }
    T* operator->() const {
        return ptr;
    }
    // get 和 release 方法
    T* get() const {
        return ptr;
    }
    T* release() {
        T* oldPtr = ptr;
        ptr = nullptr;
        return oldPtr;
    }
    // reset 方法
    void reset(T* p = nullptr) {
        if (ptr != p) {
            delete ptr;
            ptr = p;
        }
    }
};
```

---

- 替换auto_ptr
- 实现独占式拥有的概念，同一时间只能有一个智能指针可以指向该对象，因为无法进行拷贝构造和拷贝赋值，但是可以进行**移动构造和移动赋值**
- 它对于避免资源泄露、悬挂指针特别有用。
- 借助 std::move(ptr) 可以实现将一个 unique_ptr 对象赋值给另一个 unique_ptr 对象，其目的是实现所有权的转移
- 将unique_prt赋值给另—个时，如果源unique_ptr是个临时右值，编译器允许这么做；如果源unique_ptr将存在一段时间，编译器将禁止这么做

```C
unique_prt<string> pt1(new string("Hello World"));
unique_ptr<string> pt2;
pt2 = pt1;                                             // 悬挂指针pt1,报错
unique_ptr<string> pt3;
pt3 = unique_ptr<string> (new string("Hello World"));  //临时右值，编译器允许
```

### shared_ptr

- shared_ptr实现共享式拥有概念，解决悬挂指针，多个指针共享所有权，引用计数为0的时候才执行析构，通过函数传递资源
- 多个智能指针可以指向相同对象，该对象和其相关资源会在“最后一个引用被销毁”时候释放。资源可以被多个指针共享，它使用计数机制来表明资源被几个指针共享。可以通过成员函数use_count()来查看资源的所有者个数。除了可以通过new来构造，还可以通过传入auto_ptr, unique_ptr,weak_ptr来构造。当我们调用release()时，当前指针会释放资源所有权，计数减一。当计数等于0时，资源会被释放。
- 构造函数中计数初始化为1；拷贝构造函数中计数值加1；赋值运算符中，左边的对象引用计数减1，右边的对象引用计数加1；析构函数中引用计数减1； 在赋值运算符和析构函数中，如果减1后为0，则调用delete释放对象。
- shared_ptr 是为了解决unique_ptr在对象所有权上的局限性(unique_ptr是独占的), 在使用引用计数的机制上提供了可以共享所有权的智能指针。
- 成员函数：
    - use_count 返回引用计数的个数
    - make_shared创建
    - unique 返回是否是独占所有权( use_count 为 1)
    - swap 交换两个 shared_ptr 对象(即交换所拥有的对象)，
    - reset 放弃内部对象的所有权或拥有对象的变更, 会引起原有对象的引用计数的减少
    - get 返回内部对象(指针), 重载了()方法, 因此和直接使用对象是一样的.如 shared_ptrsp(new int(1)); sp 与 sp.get()是等价的

### weak_ptr

- 解决shared_ptr相互引用时，两个指针的引用计数永远不会下降为0，从而导致死锁问题。而weak_ptr是对对象的一种弱引用，可以绑定到shared_ptr，但不会增加对象的引用计数。和shared_ptr之间可以相互转化，shared_ptr可以直接赋值给它，它可以通过调用lock函数来获得shared_ptr,如果shared_ptr指向的对象中有一个方法，不能直接使用weak_ptr访问，应该通过.lock转换为shared_ptr
- weak_ptr是一种不控制对象生命周期的智能指针，它指向一个shared_ptr管理的对象
- 进行该对象的内存管理的是那个强引用的shared_ptr。weak_ptr只是提供了对管理对象的一个访问手段。
- weak_ptr设计的目的是为配合shared_ptr而引入的种智能指针来协助shared_ptr工作，它只可以从一个shared_ptr或另一个weak_ptr对象构造它的构造和析构不会引起引用记数的增加或减少。

---

- 有时，我们想在缓存中存储对象，但如果对象的主要引用被删除，我们希望缓存也能自动删除该对象。这时，可以使用 weak_ptr 来实现这种行为。
- 观察者模式：在观察者模式中，一个或多个观察者对象等待一个主题对象达到某种状态。使用 weak_ptr 可以确保观察者知道主题是否仍然存在。

### unique_ptr和shared_ptr的区别

- 选择 std::unique_ptr 还是 std::shared_ptr 取决于你是否需要共享对象的所有权。如果不需要，通常推荐使用 std::unique_ptr，因为它更轻量且效率更高。如果确实需要多个指针共享所有权，那么 std::shared_ptr 是正确的选择

---

- 所有权：
    - std::unique_ptr 表示对象的唯一所有权。即在任何时刻，只有一个 unique_ptr 可以指向一个对象。
    - std::shared_ptr 允许多个 shared_ptr 指向同一个对象。它们共同拥有该对象。
- 复制和赋值：
    - std::unique_ptr 不支持拷贝操作，但支持移动语义。这确保了对象的唯一所有权。
    - std::shared_ptr 支持拷贝和赋值。当你复制一个 shared_ptr，引用计数会增加。当一个 shared_ptr 被销毁或重新指向其他对象时，引用计数减少。
- 引用计数
    - std::unique_ptr 不使用引用计数，因为它保证对象的唯一所有权。
    - std::shared_ptr 使用引用计数来追踪有多少 shared_ptr 指向同一个对象。当引用计数变为0时，该对象被删除。
- 大小和开销
    - std::unique_ptr 的大小通常与裸指针相同，并且它没有引用计数的开销。
    - std::shared_ptr 需要额外的内存来存储引用计数，所以它的大小比 unique_ptr 大。
- 配套的弱引用：
    - std::unique_ptr 没有与之关联的弱引用版本。
    - std::shared_ptr 有一个配套的弱引用版本，叫做 std::weak_ptr。weak_ptr 可用于打破循环引用问题，因为它不会增加引用计数。
- 用途：
    - std::unique_ptr 通常用于表示对象的唯一所有权或管理资源的独占所有权。
    - std::shared_ptr 适用于需要多个指针共享同一个对象的情况。
