## 优化与故障排查

### MySQL优化流程

- 通过慢日志定位执行较慢的SQL语句
- 利用explain对这些关键字段进行分析
- 根据分析结果进行优化。避免SELECT  
    *，只选择需要的字段。避免在列上使用函数  
    
- 根据查询模式添加索引

### Explain关键字

- type：这是一个非常重要的列，表示 MySQL  
    在查询时的连接类型。不同的类型代表不同的查询性能。从最好到最差，连接类型的排序如下：  
    - system：系统表，数据已经加载到内存里。
    - const：常量连接，通过索引只需一次查找即可。
    - range：在索引上进行范围查找。
    - index：全索引扫描，比全表扫描好一点。
    - all：全表扫描，效率最差。
- key：这列显示了 MySQL  
    决定使用哪个索引。如果没有使用索引，则为空。  
    
- key_len：表示索引的长度。通常，长度越短，性能越好，因为MySQL需要处理的数据减少了。
- Extra：提供查询执行的额外信息，如：
    - Using filesort：表示 MySQL  
        需要使用外部的排序算法来对数据进行排序。这不是使用文件进行排序，而是排序操作无法使用索引，可能效率较低。  
        
    - Using  
        index：表示查询只需要从索引中获取数据，不需要实际从表中读取数据，也被称为“覆盖索引”。

### 分库分表策略

- 单表数据量太大，会极大影响sql执行性能。分表就是把一个表的数据放到多个表中，然后查询的时候查一个表。然后操作的时候你对一个用户就操作那个表就好了。这样可以控制每个表的数据量在可控的范围内，比如每个表就固定在  
    200 万以内。  
    一个库经验而言，最多支撑到并发  
    2000，一定要扩容了，而且一个健康的单库并发值最好保持在每秒 1000  
    左右，不要太大。将一个库的数据拆分到多个库中，访问的时候就访问一个库好了  
    

### 垂直拆分和水平拆分

- 水平拆分的意思，就是把一个表的数据给弄到多个库的多个表里去，但是每个库的表结构都一样，只不过每个库表放的数据是不同的，所有库表的数据加起来就是全部数据。水平拆分的意义，就是将数据均匀放更多的库里，然后用多个库来抗更高的并发，还有就是用多个库的存储容量来进行扩容。
- 垂直拆分的意思，就是把一个有很多字段的表给拆分成多个表，或者是多个库上去。每个库表的结构都不一样，每个库表都包含部分字段。一般来说，会将较少的访问频率很高的字段放到一个表里去，然后将较多的访问频率很低的字段放到另外一个表里去。因为数据库是有缓存的，访问频率高的行字段越少，就可以在缓存里缓存更多的行，性能就越好。这个一般在表层面做的较多一些。
