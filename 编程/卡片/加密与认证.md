## 加密基础

### 对称加密（Symmetric Encryption）

使用**相同密钥**加密和解密，速度快，适合大量数据。

```
明文 → [AES 加密，密钥 K] → 密文
密文 → [AES 解密，密钥 K] → 明文
```

**常见算法**：AES-128/256、ChaCha20、DES（已淘汰）

**问题**：密钥如何安全传输？→ 需要非对称加密协助交换密钥。

### 非对称加密（Asymmetric Encryption）

使用**公钥**加密，**私钥**解密（或私钥签名，公钥验签）。安全但计算开销大。

```
发送方：明文 → [公钥加密] → 密文
接收方：密文 → [私钥解密] → 明文
```

**常见算法**：RSA-2048/4096、ECC（椭圆曲线）、ECDH（密钥交换）

**HTTPS 中的组合使用**：
- 握手阶段用**非对称加密**（ECDH）协商会话密钥
- 数据传输阶段用**对称加密**（AES-GCM）加密实际数据
- 兼顾安全性和性能

详见 [[对称加密与非对称加密的区别]]

## 数字签名（Digital Signature）

**目的**：证明数据来源的真实性和完整性（防篡改 + 防抵赖）

**原理**：
```
签名过程（发送方）：
1. 对消息计算哈希值（SHA-256）
2. 用发送方的【私钥】对哈希值加密 → 数字签名
3. 发送：消息 + 数字签名

验证过程（接收方）：
1. 用发送方的【公钥】解密签名 → 得到哈希值 H1
2. 对收到的消息重新计算哈希值 H2
3. H1 == H2 → 消息真实、未被篡改
```

**与加密的区别**：
- 加密：保护内容机密性（公钥加密）
- 签名：证明来源真实性（私钥签名）

详见 [[数字签名]]

## 数字证书（Digital Certificate）

**问题**：如何验证公钥的真实性？（中间人可以伪造公钥）

**解决方案**：引入受信任的第三方——**证书颁发机构（CA）**

**X.509 证书主要内容**：
```
证书 = {
  持有者信息（域名、组织）
  持有者公钥
  有效期
  颁发者（CA）信息
  CA 的数字签名（用 CA 私钥签名）
}
```

**信任链**：
```
Root CA（内置于操作系统/浏览器）
  └── 中间 CA（由根 CA 签发证书）
        └── 服务器证书（由中间 CA 签发）
```

客户端验证服务器证书：
1. 检查证书链是否由信任的根 CA 签发
2. 验证 CA 签名的有效性（用 CA 公钥验签）
3. 检查证书是否过期、域名是否匹配、是否被吊销（OCSP/CRL）

详见 [[数字证书]]

## HTTPS 中加密与认证的结合

```
TLS 握手流程（简化）：
1. 客户端 → 服务器：ClientHello（支持的算法列表）
2. 服务器 → 客户端：ServerHello + 证书（含公钥）
3. 客户端：验证证书 → 用服务器公钥协商会话密钥（ECDH）
4. 双方：用会话密钥（对称）加密后续通信
```

详见 [[HTTPS的连接过程]]
