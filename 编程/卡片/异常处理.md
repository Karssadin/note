## C++ 异常处理机制

C++ 通过 `try`/`catch`/`throw` 实现异常处理，用于**错误信号传递**和**资源安全清理**。

---

## 基本语法

```cpp
try {
    // 可能抛出异常的代码
    if (error)
        throw std::runtime_error("发生了错误");
} catch (const std::runtime_error& e) {
    std::cerr << "RuntimeError: " << e.what() << "\n";
} catch (const std::exception& e) {
    std::cerr << "Exception: " << e.what() << "\n";
} catch (...) {
    // 捕获所有异常（包括非 std::exception 类型）
    std::cerr << "Unknown exception\n";
}
```

- `throw` 后面跟异常对象（任意类型，通常继承自 `std::exception`）
- `catch` 按顺序匹配，**先具体后通用**
- `catch (...)` 捕获所有类型的异常

---

## 标准异常层次体系

```
std::exception
├── std::logic_error        — 程序逻辑错误（应当在编写时避免）
│   ├── std::invalid_argument
│   ├── std::out_of_range
│   ├── std::length_error
│   └── std::domain_error
├── std::runtime_error      — 运行时无法预测的错误
│   ├── std::range_error
│   ├── std::overflow_error
│   └── std::underflow_error
├── std::bad_alloc          — new 分配失败
├── std::bad_cast           — dynamic_cast 失败
├── std::bad_typeid         — typeid 失败
└── std::bad_exception      — unexpected() 中抛出的异常
```

## 栈展开（Stack Unwinding）

异常抛出后，C++ 运行时沿调用栈**逐层返回**，依次调用局部对象的析构函数，直到找到匹配的 `catch`：

```cpp
void f3() { throw std::runtime_error("error"); }
void f2() { Resource r; f3(); }  // f3 抛出，r.~Resource() 自动调用
void f1() {
    try { f2(); }
    catch (const std::exception& e) { /* 在这里捕获 */ }
}
```

**重要**：若没有匹配的 `catch`，异常传到 `main()` 外，调用 `std::terminate()`。

## 异常安全保证

| 级别 | 含义 | 实现方式 |
|------|------|---------|
| **nothrow** | 保证不抛出（`noexcept`）| 析构函数、swap、move 应达到此级别 |
| **strong** | 失败则回滚，状态不变 | copy-and-swap 惯用法 |
| **basic** | 失败后资源无泄漏，对象处于有效状态 | RAII |
| **none** | 无保证，应避免 | 不建议 |

## 自定义异常类

```cpp
class NetworkError : public std::runtime_error {
    int error_code;
public:
    NetworkError(const std::string& msg, int code)
        : std::runtime_error(msg), error_code(code) {}
    int code() const { return error_code; }
};

// 使用
try {
    throw NetworkError("连接超时", 408);
} catch (const NetworkError& e) {
    std::cout << e.what() << " (code=" << e.code() << ")\n";
} catch (const std::exception& e) {
    // 基类 catch 兜底
}
```

## 重新抛出异常

```cpp
try {
    do_something();
} catch (const std::exception& e) {
    log(e.what());
    throw;   // 重新抛出原始异常（保留类型和信息）
    // 不要写 throw e; — 会发生切片（slice）丢失派生类信息
}
```

## 异常 vs 错误码

| 维度 | 异常 | 错误码 |
|------|------|--------|
| 适用场景 | 意外的、非正常的错误 | 预期内的、频繁的返回状态 |
| 性能 | 抛出时有开销（零开销路径除外）| 无额外开销 |
| 代码简洁性 | 高（无需逐层传递）| 低（每层都要检查） |
| 与 RAII 结合 | 天然结合，自动清理 | 需手动 cleanup |
| 推荐使用 | 构造失败、IO 错误等 | 状态码、频繁调用的函数 |
