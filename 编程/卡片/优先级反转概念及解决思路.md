## 什么是优先级反转（Priority Inversion）

**优先级反转**是实时系统/并发编程中的经典问题：高优先级任务因被低优先级任务间接阻塞而无法运行。

### 经典场景

```
任务优先级：H（高）> M（中）> L（低）

1. L 获取锁 μ，进入临界区
2. H 被调度运行，尝试获取 μ → 阻塞（等待 L 释放）
3. M 抢占 L，开始运行（M 不需要 μ）
4. M 长时间运行 → L 无法释放 μ → H 持续阻塞
```

**结果**：M 的优先级实际上"高于"H，发生优先级反转。

### 历史案例：火星探路者（1997）
NASA 火星探路者因优先级反转导致系统频繁重启。实时任务（高优先级）被长时间运行的低优先级任务阻塞，最终触发看门狗超时重启。后通过启用**优先级继承**修复。

---

## 解决方案

### 1. 优先级继承（Priority Inheritance）

当高优先级任务 H 等待低优先级任务 L 持有的锁时，**临时将 L 的优先级提升至 H 的级别**，直到 L 释放锁。

```
修复后：
1. L 获取锁 μ（优先级=低）
2. H 尝试获取 μ → 阻塞，同时 L 的优先级临时提升为 H 的优先级
3. L（以 H 的优先级运行）抢占 M，执行完临界区，释放 μ
4. L 优先级恢复原值，H 获取 μ，正常运行
```

**优点**：动态、自动  
**缺点**：实现复杂，可能导致"链式继承"，多个锁嵌套时性能下降

POSIX 线程支持：`pthread_mutexattr_setprotocol(PTHREAD_PRIO_INHERIT)`

### 2. 优先级天花板协议（Priority Ceiling Protocol, PCP）

预先为每个资源设置**优先级天花板**（= 所有可能访问该资源的任务中的最高优先级）。

规则：
- 任务申请锁时，若锁的天花板 ≥ 当前系统中所有持锁任务的优先级，才允许获取
- 持锁期间，任务的优先级提升至锁的天花板

**优点**：防止死锁、避免链式阻塞，阻塞时间有界  
**缺点**：天花板需要静态预分配，灵活性低

POSIX：`pthread_mutexattr_setprotocol(PTHREAD_PRIO_PROTECT)` + `pthread_mutexattr_setprioceiling`

### 3. 避免阻塞（无锁方案）

使用**无锁（Lock-free）数据结构**（基于原子操作 CAS），彻底消除等待锁导致的优先级反转。

适用于：高实时性场景，队列/计数器等简单数据结构

### 4. 资源预留

在确定的时间间隔内，只有特定优先级的任务可以访问资源，确保高优先级任务总能在预测时间内获得资源。

适用于：硬实时系统（RTOS）

## 对比总结

| 方案 | 动态/静态 | 防死锁 | 实现复杂度 | 适用场景 |
|------|---------|--------|---------|---------|
| 优先级继承 | 动态 | 否 | 中 | 通用实时系统 |
| 优先级天花板 | 静态 | 是 | 高 | 严格实时系统 |
| 无锁数据结构 | — | 是 | 高 | 高并发，数据结构简单 |
| 资源预留 | 静态 | 是 | 低 | RTOS |
