## 调度基本概念

**进程调度**：在多个就绪进程中选择一个分配 CPU 的机制，分为：
- **抢占式（Preemptive）**：运行中的进程可以被强制换出（支持更好的响应性）
- **非抢占式（Non-preemptive）**：进程主动让出 CPU（简单，但响应性差）

---

## 常用调度算法

### 先来先服务（FCFS）
- **策略**：按到达顺序排队，非抢占
- **优点**：简单公平
- **缺点**：不利于短作业，可能产生**护航效应**（短作业等待长作业）

### 时间片轮转（Round Robin）
- **策略**：每个进程轮流执行固定时间片，抢占式
- **优点**：响应时间均匀，适合分时/交互系统
- **缺点**：时间片过小→频繁上下文切换；时间片过大→退化为 FCFS

### 短作业优先（SJF）
- **策略**：选择估计运行时间最短的进程，非抢占
- **优点**：平均等待时间最短（理论最优）
- **缺点**：需要预知执行时间；**长作业可能饥饿**

### 最短剩余时间优先（SRTF/STRF）
- SJF 的抢占版本，每次新进程就绪时重新调度
- **优点**：最优平均周转时间
- **缺点**：长进程饥饿风险更严重

### 高响应比优先（HRRN）
- 响应比 = `(等待时间 + 执行时间) / 执行时间`，每次选响应比最高者
- 综合考量等待时间和长度，兼顾长短作业
- **缺点**：需要准确的执行时间估计

### 优先级调度（Priority）
- 每次选最高优先级进程（可抢占或非抢占）
- **缺点**：低优先级进程可能**饥饿**（通过**老化 Aging** 解决：等待越久优先级越高）
- 引发**优先级反转**问题，见 [[优先级反转概念及解决思路]]

## 算法对比表

| 算法 | 抢占性 | 饥饿风险 | 适用场景 | 平均等待时间 |
|------|--------|---------|---------|------------|
| FCFS | 非抢占 | 否 | 批处理 | 差 |
| 时间片轮转 | 抢占 | 否 | 分时/交互 | 中等 |
| SJF | 非抢占 | 长作业有 | 批处理（已知时间）| 最优 |
| SRTF | 抢占 | 长作业有 | 理论最优 | 最优 |
| HRRN | 非抢占 | 否（老化）| 批处理 | 较优 |
| 优先级 | 可选 | 低优先级有 | 实时/嵌入式 | 取决于分配 |
| 多级反馈队列 | 抢占 | 几乎无 | 通用 OS | 良好 |

## 调度性能指标

| 指标 | 定义 |
|------|------|
| CPU 利用率 | CPU 处于忙碌状态的时间占比 |
| 系统吞吐率 | 单位时间内完成的进程（作业）数 |
| 响应时间 | 从提交请求到首次响应的时间（交互系统关键） |
| 周转时间 | 从提交到完成的总时间 |
| 平均周转时间 | 所有进程周转时间的平均值 |
| 带权周转时间 | 周转时间 / 实际运行时间（衡量长短作业的公平性）|

## 多级反馈队列（Linux O(1) 调度）

现代通用 OS 常用**多级反馈队列（MLFQ）**：
1. 设置多个优先级队列，各队列有不同时间片长度
2. 新进程进入最高优先级队列
3. 若用完时间片仍未完成，降级到下一队列（惩罚 CPU 密集型）
4. 等待过久则升级（防止饥饿）

Linux CFS（完全公平调度器）使用红黑树，按**虚拟运行时间（vruntime）**选择最小者运行，从而实现公平调度。
