结构型模式。将一个类的接口**转换成**客户期望的另一个接口，让原本接口不兼容的类可以协同工作。

## 解决了什么问题

已有类的接口和所需接口不兼容，又不想修改已有代码（如第三方库）。

- **稳定点**：目标接口（客户期望的接口）
- **变化点**：被适配者（已有类）的接口

## 类适配器（继承）

```cpp
// 目标接口（客户期望）
class Target {
public:
    virtual string request() = 0;
    virtual ~Target() {}
};

// 被适配者（已有的第三方类，接口不兼容）
class Adaptee {
public:
    string specificRequest() { return "Adaptee's data"; }
};

// 类适配器（多重继承）
class ClassAdapter : public Target, private Adaptee {
public:
    string request() override {
        return "Adapted: " + specificRequest();
    }
};
```

## 对象适配器（组合，推荐）

```cpp
// 对象适配器（持有 Adaptee 实例）
class ObjectAdapter : public Target {
    Adaptee* adaptee;
public:
    ObjectAdapter(Adaptee* a) : adaptee(a) {}
    string request() override {
        return "Adapted: " + adaptee->specificRequest();
    }
};

// 使用
Target* t = new ObjectAdapter(new Adaptee());
t->request();
```

## 与其他结构型模式的区别

| 模式 | 意图 |
|------|------|
| 适配器 | 接口转换，解决不兼容 |
| 装饰器 | 同接口增强功能 |
| 代理 | 同接口控制访问 |
| 外观 | 简化一组接口 |

## 应用案例

- STL 容器适配器：`stack`/`queue`/`priority_queue` 适配 `deque`/`vector`
- 将旧 C 接口封装成 C++ 类接口
- 数据库驱动适配（ODBC、JDBC）
